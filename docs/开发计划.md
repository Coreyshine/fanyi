# fanyi — 本地模型实时页面翻译器（方案二：本地服务 + 浏览器扩展）

## 已确认的决策
- **形态**：C/C++ 托盘常驻翻译服务（llama.cpp 推理 + localhost HTTP API）+ 浏览器扩展（Chrome/Edge/Firefox 通用，MV3），在你的现有浏览器里翻译所有页面
- **模型**：`Hy-MT2-1.8B`（hunyuan-dense 架构，已确认 llama.cpp 2025年7月后版本支持）
- **量化版本：选 Q8_0（1.9GB）** — 理由：你明确要求"翻译精准"，Q8_0 接近无损（Q6_K/Q4_K_M 对翻译细微语义有可测劣化），而体积代价仅比 Q6_K 多 0.4GB（相对模型本身可忽略）；Q8_0 在 CPU 上仍流畅。Q6_K 作为低内存机器的备选写入文档，模型路径可在设置里改
- **加速**：CPU（macOS 自动启用 Metal，不增体积）；不开 CUDA
- **核心要求落实**：外文占比 >60% 自动翻译（阈值可调）、页面悬浮开关、设置页选语言对（默认英→汉）、资源占用低（懒加载、空闲卸载、可见区域优先、批量+缓存）、体积小（程序几 MB，无 Chromium 打包）

## 关键设计
- **翻译提示词**（混元官方格式）：`把下面的文本翻译成{目标语言}，不要额外解释。`，无 system prompt；聊天模板用 GGUF 内置，加载失败则回退硬编码混元模板
- **性能**：单推理线程 + 请求合并；一个 llama_batch 挂多条 sequence 共享指令前缀（页面 30–100 段几秒内完成，逐段流式返回）；KV cache q8_0、mmap、flash-attn 降内存；空闲 N 分钟自动卸载模型（可关）
- **检测**：扩展端脚本级判断（CJK 区段/拉丁文+常用语言停用词表，很小）；目标语言为中文时非 CJK 拉丁文本即外文，占比 >60% 触发
- **安全**：仅监听 127.0.0.1 + Origin 白名单（仅本扩展），防恶意网页调用
- **语言表**：常用 15 种（中/英/日/韩/法/德/西/俄/葡/意/阿/泰/越/印尼等，模型实际支持 33 种）

## 实施步骤
1. **脚手架 + 模型拷贝**：git init；检查/安装 cmake；clone 固定版 llama.cpp；从 `/Volumes/3T HDD/models1/Hy-MT2-1.8B-GGUF/` 拷贝 Q8_0 到 `models/` 并校验大小
2. **C 翻译核心**：translator.c + CLI 测试程序，验证模型加载与翻译质量（中英互译抽查）
3. **HTTP 服务 + 配置**：流式翻译端点、配置读写、settings 页面（默认英→汉、阈值 60%）
4. **浏览器扩展**：取词/占比检测/悬浮开关/流式替换/SPA 监听/缓存；Chrome 开发者模式加载验证
5. **托盘与自启**：macOS 先行（本机），Windows/Linux 代码同期交付；BUILD.md 三平台说明
6. **端到端验证**：起服务→浏览器装扩展→打开英文网页验证自动翻译、悬浮开关、设置持久化；用 browser-use 自动化回归；记录首字延迟/整页耗时/内存占用

## 风险与对策
- llama.cpp 版本必须新（hunyuan-dense 2025-07 才支持）→ 固定较新 release 并在配置时校验架构支持
- 混元 GGUF 若缺 chat_template → 回退硬编码模板
- Linux Wayland 托盘兼容性参差 → 托盘设为可选编译项，服务本身无 GUI 依赖
- 模型许可：腾讯混元社区许可，本地使用无碍，文档注明出处
